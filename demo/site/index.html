Incident Copilot

An AI on-call agent. A real microservice system (4 services, Postgres, Redis) ran on GitHub Actions with OpenTelemetry, Prometheus and structured logs while 15 production incidents were injected: bad deploys, a dropped index, lock contention, a hung cache, a failing payment provider, memory leaks and decoy deploys. When the alert fires, the agent investigates the recorded telemetry with tools, the way an engineer would, and writes a root-cause report with evidence. A human must approve any fix.

How it works

1. Record real incidents. For each scenario, a GitHub Actions runner starts the system in Docker Compose, sends steady traffic, injects the fault (a deploy with a bug or bad setting, a SQL change, a paused container, a degraded external provider) and records metrics, alerts, logs, traces and deploy history. Decoy deploys happen in some scenarios, like in real life.

2. Investigate like an engineer. When the first alert fires, the agent gets the page and only the data available up to that moment. It calls tools: service overview, metrics, grouped logs, slow and failing traces, deploy history, and semantic search over the team's runbooks. Every tool result has an evidence id.

3. A report that can be checked. The answer must use a fixed cause vocabulary and cite at least two evidence ids the tools really returned; fabricated citations are rejected. Remediation is limited to safe actions and always requires human approval.

4. Measured, not anecdotal. Every incident has a known cause. The agent is compared with a "blame the last deploy" rule and across several free LLMs, with confidence intervals.
